# NikkeCR

**한국어** · [English](README.en.md) · [MIT License](LICENSE)

NIKKE PC 런처 침해 사고의 알려진 흔적을 탐지하고, 근거가 있는 항목을 백업한 뒤 복구하는 Windows 도구입니다. `NikkeCR.exe`의 **탐지**와 **복구** 두 버튼으로 사용합니다. **실행로그** 탭에서 진행 상황과 실패 항목을 확인할 수 있습니다.

**현재 버전: 0.4.4-preview. 완전한 치료, 유출 목록의 완전한 복원, 포맷이 필요 없다는 보장을 제공하지 않습니다.** 코드가 알 수 없는 추가 악성코드와 이미 탈취된 계정은 별도로 대응해야 합니다.

## 실행 파일 위치

**[Windows 실행 파일 ZIP 다운로드](https://github.com/v3s9er/NikkeCR/releases/download/v0.4.4-preview/NikkeCR-0.4.4-preview-win-x64.zip)** → 압축 해제 → **`NikkeCR\NikkeCR.exe`** 실행.

예를 들어 `C:\Tools`에 풀었다면 실행 경로는 **`C:\Tools\NikkeCR\NikkeCR.exe`**입니다. `NikkeCR.exe`만 따로 옮기지 말고 같은 폴더의 `scripts`, `engine`, `data`, 무결성 목록을 함께 두세요.

**저장소 루트에도 [NikkeCR.exe](NikkeCR.exe)를 포함합니다.** 저장소에서 받으려면 **Code → Download ZIP**으로 전체 폴더를 내려받아 압축을 풀고 `NikkeCR-main\NikkeCR.exe`를 실행하세요. EXE 하나만 내려받으면 필요한 스크립트와 무결성 목록이 없어 실행할 수 없습니다.

## 사용법

1. [Releases](https://github.com/v3s9er/NikkeCR/releases)에서 Windows x64 ZIP을 내려받고 동기화·심볼릭 링크가 없는 로컬 폴더에 압축을 풉니다. `NikkeCR.exe`, `scripts`, `engine`, `data`, 무결성 목록을 함께 두세요.
2. 압축을 푼 폴더의 `NikkeCR\NikkeCR.exe`를 실행하고 **탐지**를 누릅니다. Security 로그 등에 접근하려면 `관리자 권한으로 탐지`를 선택하고 정상적인 Windows UAC 창을 승인합니다.
3. 이전에 보존한 원본 런처 로그가 있으면 `보존한 증거 폴더`에 경로를 입력할 수 있습니다. 선택 사항이며 분석 보고서 문장을 실행 증거로 받아들이지 않습니다. 당시 HTTP 기록이 있으면 HAR 파일을 지정할 수 있습니다. 이 도구가 과거 트래픽을 새로 만들어 내지는 않습니다.
4. 결과의 근거와 검사하지 못한 항목을 읽습니다. **복구**를 누르면 조치 계획을 표시합니다. 승인한 뒤 Windows 관리자 권한으로 백업·차단·격리·사후 확인을 수행합니다.
5. 적재된 DLL이 남아 있다고 나오면 작업을 저장하고 표시된 앱을 완전히 종료한 후 다시 탐지합니다. 앱 강제 종료나 재부팅은 자동으로 하지 않습니다.

결과와 로그·백업은 해당 사용자의 `%USERPROFILE%\NikkeCR-Evidence\Runs\<실행 ID>`에 보관합니다. `result.json`, `report.html`, `progress.log`, `history.json`, `settings.json`과 `engine` 아래 원본 조사 기록을 확인하세요. 개인정보가 포함될 수 있으므로 공개 이슈에 폴더 전체를 올리지 마세요. 자동 업로드·원격 측정·비밀번호 복호화·Defender 전체검사 실행은 없습니다.

## 결과를 읽는 법

| 표시 | 의미 |
| --- | --- |
| 전송 기록 · 주황 | 제공된 HAR에서 알려진 전송 주소·POST 본문·비어 있지 않은 값·2xx 응답을 확인했습니다. 기록의 진위와 수집 PC가 별도로 검증되지 않아 실제 유출로 확정하지 않습니다. 값은 해시만 보관합니다. |
| 실제 유출 · 빨강 | 수집 PC와 전송 내용까지 뒷받침되는 증거를 위한 구분입니다. 현재 버전은 HAR만으로 이 상태를 자동 생성하지 않으며 미확정으로 표시합니다. |
| 알려진 위협 · 주황 | 현재 DLL·COM 등록·프로세스 적재 지표입니다. 탐지 근거에 따라 정확한 해시와 결합된 구조 지표를 구분합니다. |
| 노출 가능 · 주황 | 악성코드의 수집 대상 경로가 이 프로필에 존재합니다. 파일 존재는 실제 수집 또는 유출 증거가 아닙니다. |
| 수집 흔적 · 주황 | 알려진 임시 수집물과 이름이 일치합니다. 내용·실행 주체·전송 완료 여부는 미확정입니다. |
| 추가 확인 필요 / 검사하지 못함 | 접근 거부, 로그 비활성화, 조회 한도, 설명되지 않은 실행 관계 등입니다. 안전으로 처리하지 않습니다. |
| 복구 후 확인 | 해당 조치의 후속 검사까지 완료했습니다. 전체 PC가 안전하다는 뜻은 아닙니다. |

**실제 유출 확인이 0개여도 유출되지 않았다는 뜻은 아닙니다.** DNS·접속 기록·SRUM 바이트 수·에이전트 카운터만으로 탈취 파일이나 계정 목록을 확정하지 않습니다. 그림이나 숫자의 녹색 안전 판정은 제공하지 않습니다.

## 작동 원리와 범위

- `platform_experience_helper.dll`의 정확한 SHA-256과 엄격한 파일 구조 지표, 알려진 사용자 COM 등록, 메모리 적재 상태, Lua 구조 흔적을 조사합니다. 정상 Chrome의 `PlatformExperienceHelper` 폴더 전체를 지우지 않습니다.
- 확인한 Lua의 100개 서비스·220개 고유 경로, 추가 수집 기능, DLL의 28개 지갑 대상 정보를 [정적 기능 목록](data/static-capabilities.json)에 담았습니다. 기본 명령 14개, Lua 함수 277개와 DLL 함수 703개의 분석이 근거입니다. 함수 목록 완성은 모든 동작의 실행 검증을 뜻하지 않습니다.
- 개발·클라우드 자격증명, 브라우저 로그인·쿠키, NIKKE 저장 로그인, 화면, 시스템 정보, 임의 파일·명령 결과를 구분합니다. 자격증명 본문을 열어 보거나 실제 비밀번호를 복호화하지 않습니다.
- 설치 프로그램, 시작 항목, 작업·서비스·드라이버 등록, WMI, 브라우저 정책과 참조 파일을 제한된 시간·개수 안에서 조사합니다. Sysmon/Security/System/TaskScheduler/Application/DNS 로그를 읽고, 제공되는 경우 `ProcessGuid`로 실행 관계를 연결합니다. 같은 PID라는 이유만으로 서로 다른 프로세스를 연결하지 않습니다.
- 런처 원본 `debug.log`의 에이전트 시작 표식과 임시 수집물 이름을 검사합니다. 원본 로그의 조작 가능성과 보존 공백은 남습니다. 이벤트 로그는 2026-09-27 이후 각 원본별 최근 3,000건을 조회하며 한도·접근 실패를 표시합니다.
- 복구는 알려진 통신 차단, 사용자 COM 변조 제거, 해시 검증한 DLL 보존·격리, 런처 캐시 보존·격리에 한정됩니다. 탐지 때 검토한 조치에 없는 새 항목은 실행하지 않습니다. 런처 통신 차단으로 게임 연결이 막힐 수 있습니다.
- 추가 설정 복구는 알려진 공격자 도메인의 사용자 PAC URL 또는 알려진 DLL 해시를 직접 참조하는 사용자 Run/RunOnce 값처럼 좁은 조건을 만족하는 항목만 지원합니다. 삭제 전 원래 값과 형식을 저장하고, 변경 여부와 결과를 재검증합니다. 다른 정책·프록시·서비스는 조사 대상으로 남깁니다.
- 파일 해시 목록은 변경·손상을 확인하는 수단입니다. 게시자의 신원이나 손상된 PC의 신뢰성을 보증하는 코드 서명은 아닙니다. 배포본은 현재 서명되지 않았습니다.

## 사후 복구와 한계

이 도구는 프로그램 전체를 무조건 재설치하거나 모든 설정을 초기화하지 않습니다. 정상 버전·제조사 원본·감염 전 기준점이 없으면 무엇으로 되돌려야 하는지 알 수 없기 때문입니다. 포함된 [고급 엔진 설명](engine/README-ko.md)의 무결성 기준점 및 선택적 파일 복원 기능은 검증한 동일 버전 원본 ZIP이 있을 때만 별도로 사용합니다. 일반 GUI 복구 버튼이 모든 프로그램 파일을 교체하는 것은 아닙니다.

사후 관찰은 포함된 `engine/Invoke-NikkeAftercare.ps1`로 현재 상태와 이전 기준점을 비교할 수 있습니다. 정기 작업은 자동으로 설치하지 않습니다. [엔진 설명](engine/README-ko.md)의 등록·해제 방법과 검토 대기 목록을 확인하세요. 계정 비밀번호, API 토큰, SSH 키, 로그인 세션은 신뢰할 수 있는 다른 기기에서 별도로 폐기·교체해야 합니다.

정확한 로컬 Lua와 당시 악성 `l.js`는 확보하지 못했습니다. 정적 분석한 Lua는 로컬 실행본과 동일하다고 입증되지 않았습니다. 추가 `exec` 실행, 미지의 변종, 다른 사용자·비기본 프로필, 삭제된 증거, 커널·펌웨어 변조, 모든 프로그램 플러그인을 배제하지 못합니다. SRUDB/USN 직접 파싱과 삭제 파일 복구도 구현되어 있지 않습니다. 기존 로그가 없으면 과거 전송 내용을 사후에 전부 복원할 수 없습니다.

## 빌드와 검증

Windows x64, Windows PowerShell 5.1 및 .NET Framework가 필요합니다. 저장소 루트에서 다음을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build.ps1 -Package
powershell -NoProfile -ExecutionPolicy Bypass -File tests\Test-NikkeCR.ps1
```

빌드 후 실행 파일은 저장소 루트의 `NikkeCR.exe`, 배포 ZIP은 `dist\NikkeCR-0.4.4-preview-win-x64.zip`에 생성됩니다.

`Build.ps1`은 설치된 .NET Framework C# 컴파일러를 사용하며 외부 패키지를 내려받지 않습니다. [검증 기록](docs/VALIDATION.md)에 실제로 수행한 범위와 미완료 범위를 구분합니다.
